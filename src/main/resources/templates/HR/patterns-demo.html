Design Patterns Implementation Demo

1. DTO (Data Transfer Object) Pattern

Purpose: Decouple internal entities from external interfaces

Implementation: EmployeeDTO, LeaveRequestDTO, DashboardDTO

Benefits: Improved security, reduced data transfer, better API design

View Employees as DTOs

View Dashboard Data as DTO

2. Strategy Pattern

Purpose: Define different approval strategies for leave requests

Implementation: LeaveApprovalStrategy interface with ManagerApprovalStrategy, HRApprovalStrategy, AdminApprovalStrategy

Benefits: Flexible approval rules, easy to extend with new strategies

Test Approval Strategies

3. Observer Pattern

Purpose: Notify multiple components when employee events occur

Implementation: EmployeeObserver interface with EmailNotificationObserver and AuditLogObserver

Benefits: Decoupled event handling, extensible notification system

Note: Observer pattern is automatically triggered when you add, update, or delete employees through the existing forms.

4. Singleton Pattern

Purpose: Ensure single instance of application configuration

Implementation: ApplicationConfig class with synchronized getInstance() method

Benefits: Shared configuration state, resource management, consistent settings

View Application Configuration

Integration Points

HrService: Integrated with Observer pattern for employee events

LeaveService: Integrated with Strategy pattern for approval logic

Controllers: Use DTOs for data transfer and Singleton for configuration

DTOMapperService: Centralized conversion between entities and DTOs

Testing the Patterns

To test Observer Pattern:

  • Go to Add Staff and create a new employee
  • Check console logs for observer notifications
  • Edit or delete an employee to see update/delete notifications

To test Strategy Pattern:

  • Visit the Strategy Demo page
  • See how different user roles have different approval capabilities

To test DTO Pattern:

  • Visit the Employees DTO page
  • See how entities are converted to DTOs for external consumption

To test Singleton Pattern:

  • Visit the Config Info page
  • See application configuration managed by singleton
